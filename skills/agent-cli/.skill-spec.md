# skill-spec: agent-cli

- **name**: agent-cli
- **description**: Design and build command-line tools in Rust whose first reader is an AI agent. Fires when the user wants a new CLI, a new subcommand, or is deciding a CLI's output, errors, help or release.
- **origin**: extracted from `sunfmin/afkconvoy` (ADR-0001, ADR-0007, `gate.sh`, `verify.sh`, `packaging/release.sh`, `tests/help.rs`). The Scoop part is not from that repo: it has never been run.
- **target**: dedicated repo `sunfmin/agent-cli`
- **visibility**: public

## should_fire

1. 帮我做一个给 agent 用的命令行工具，用来查一个站点里的死链
2. I want to build a new CLI that syncs my Linear issues to local markdown. Design it.
3. 我这个 CLI 要加一个子命令 export，输出应该长什么样？报错怎么设计？
4. How should the --help of my command-line tool be written so an AI agent can learn the tool from it?
5. 我的命令行工具要发布了，怎么让人在 mac、Linux 和 Windows 上装？

## needs

Nothing bundled. The tools the skill names (cargo, Flux, fixpoint, z3, cargo-nextest, Homebrew, Scoop) are the built tool's, not the skill's.

## functional_test

Task: with only this SKILL.md as guidance, design (not build) a CLI `deadlinks` that
finds dead links in a directory of markdown files — workspace layout, the top-level
help guide, one subcommand's help, sample stdout for a success, an expected outcome
and a failure, and the release plan.

Success, each checkable in the output:

1. A cargo workspace with at least one pure crate and exactly one effect crate; no pure crate does I/O.
2. The pure crates are checked by Flux, with at least one bound or order rule named.
3. Every sample stdout is exactly one JSON object; the failure is `{"error": …}` with a non-zero exit; the expected outcome exits 0.
4. A `doctor` command and a command that changes nothing.
5. The top-level guide has the six parts; the subcommand help has the five parts.
6. No state kept by the process.
7. Release: tag equals version, `packaging/release.sh` subcommands, macOS + Linux + Windows, Homebrew formula and Scoop manifest both generated.
